2.2. Quatro Pilares Arquiteturais Descritos na Documentação Técnica (DOCUMENTADO, MAS NÃO VERIFICADO no código 0.9.17)

A Seção 2.1 do Relatório Técnico Sun Rustinho v0.9.17.md (página 51) e o Capítulo 11.1 do dossiê (página 16) descrevem quatro pontos fortes da arquitetura entre Rust, C++, Qt6 e QML:   
Log_Consolidado_Rustinho_0.9.17.pdf+ 1

    Fronteira limpa entre Domínio e UI (rustinho-nucleo ↔ app): A comunicação entre a interface e o núcleo ocorre exclusivamente por comandos JSON através de Servico::chamar (nucleo/src/api.rs) e Sistema (app/src/ponte.rs). O relatório destaca que não há vazamento de tipos SQL (rusqlite) para a camada C++/QML, o que permite testes de integração determinísticos sem necessidade de interface gráfica.   
    Log_Consolidado_Rustinho_0.9.17.pdf+ 2

    Execução assíncrona protegida na ponte FFI (app/src/ponte.rs): O relatório descreve o uso de AtomicBool (ocupado) combinado com std::panic::catch_unwind e qt_thread().queue(...) nas funções chamar_demorado e abrir_em_segundo_plano, com a finalidade de impedir o congelamento da thread de renderização do Qt (GUI thread) e prevenir undefined behavior causado por stack unwinding através da fronteira FFI C++/Rust.   
    Log_Consolidado_Rustinho_0.9.17.pdf+ 1

    Aritmética financeira segura: O relatório afirma que o perfil de release mantém overflow-checks = true no Cargo.toml e que os cálculos de rateio (compras::ratear) utilizam inteiros intermediários i128 com saturação explícita (numeros::saturar) para evitar estouro de inteiros.   
    Log_Consolidado_Rustinho_0.9.17.pdf+ 1

    Componentização QML de Base (Design System): Os componentes visuais reutilizáveis (Faixa.qml, Painel.qml, Campo.qml, Botao.qml, IconeFuncao.qml, Notificacao.qml, Guia.qml, ConflitoCnpj.qml) são descritos como integrantes de um design system centralizado no singleton Tema.qml.
